# Project brief

## Purpose

Provide a low-cost place to practice fundamentals, test interests, and produce
selected evidence that can inform later end-to-end projects.

## What belongs here

- A bounded question that can be answered and documented.
- A from-scratch implementation chosen for conceptual value.
- A small feasibility experiment before committing to a dedicated project.
- A polished exercise whose evaluation and conclusion teach something concrete.

## What does not belong here

- An uncurated dump of course files or abandoned notebooks.
- A substantial product with its own users and lifecycle.
- Large datasets, secrets, model weights, or opaque generated output.
- Paper reproduction selected only because the paper is fashionable.

## Exercise completion checklist

1. State the question and why it matters.
2. Describe the data, assumptions, and risks.
3. Establish a simple credible baseline.
4. Use a validation design consistent with how the data was generated.
5. Report metrics with context and analyze representative errors.
6. Record what changed, failed, and remains uncertain.
7. Make reproduction steps clear and decide whether the result is publishable.

## Open decisions

- First exercise and its time box.
- Python environment and dependency conventions.
- Notebook execution and automated quality checks.
- Criteria for graduating an experiment into a dedicated repository.
